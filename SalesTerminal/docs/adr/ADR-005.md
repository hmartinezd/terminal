# ADR-005: Exact decimal money; no Float/Double

## Status
Accepted

## Context
Financial calculations require exact precision to avoid rounding errors common with floating-point types.

## Decision
We will use `BigDecimal` (wrapped in a `Money` class) for all financial values and quantities. `Float` and `Double` are strictly prohibited for canonical financial data.

## Consequences
- Predictable and correct financial arithmetic.
- Explicit control over rounding according to currency monetary precision.
