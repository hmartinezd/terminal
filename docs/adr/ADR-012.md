# ADR-012: Offline subscription licensing and device-bound security

## Decision

Sales Terminal uses renewable, offline license leases signed by a licensing authority with ECDSA P-256/SHA-256. The APK contains only the configured X.509 public verification key; the authority private key is never generated, stored, or used by the Android application. `LicensePayloadV1` is signed over documented ordered, length-prefixed UTF-8 fields rather than JSON formatting.

Each installation creates a non-exportable P-256 identity key in Android Keystore. `deviceKeyId` is Base64URL(SHA-256(public-key encoding)); a 128-bit grouped display prefix is the support-friendly Device Code. Activation exports only restaurant, terminal, device, request, and time metadata. Renewal imports a higher-sequence signed envelope through the Storage Access Framework. The issuer enforces subscription terminal counts; device replacement requires reactivation and reissue.

Accepted envelopes are durably stored and reverified on every evaluation; persistence is not authority. Every protected selling mutation performs one authoritative current evaluation of signature, identity and product bindings, device binding, app integrity, trusted time, and validity boundaries. It never authorizes from the reactive cache. A one-minute active-process refresh and foreground refresh keep the UI current, but neither is the security boundary. Valid and expiring-soon leases allow selling; grace allows selling with warning; after grace all sale mutations are denied below the UI. History, reports, printing, export, settings, discard of open orders, and historical void remain available. Licensing never mutates or deletes sales.

Increasing `licenseSequence` prevents downgrade. `highestAcceptedLicenseSequence` and `lastTrustedUtc` are fields in one deterministically serialized, versioned security state authenticated in full by the Keystore HMAC key. The sequence floor never decreases. Equal-sequence licenses are duplicates when their canonical payload bytes match; ECDSA signature bytes are intentionally ignored because independently valid signatures need not be identical. A different payload at the same sequence is a conflict. Unverified local envelope fields are never used for downgrade decisions. If the authenticated floor exists but its matching valid envelope is unavailable, comparison fails safely; a valid authority-signed higher sequence is the supported recovery path.

Trusted time preserves the greatest observed UTC floor. A five-minute backward correction tolerance and an in-session `elapsedRealtime` estimate detect ordinary wall-clock rollback. A newly accepted authority-signed `issuedAtUtc` may advance, never reduce, this floor. Reads check whether the HMAC alias exists without creating it: absence of both key and state is first initialization, while missing state with an existing key is suspicious and fails closed. If the device was powered off while fully offline, the application cannot prove elapsed calendar time after pre-boot clock manipulation without an external trusted clock; short renewable leases limit that exposure.

Release builds also verify the installed signing-certificate SHA-256 fingerprint, fail closed (without propagating platform inspection exceptions) for missing/invalid license authority or certificate configuration, and enable R8 minification, obfuscation, and resource shrinking. CI assembles the minified release with an explicitly non-production test public key and placeholder certificate hash; real packaging still requires production `LICENSE_AUTHORITY_PUBLIC_KEY` and `EXPECTED_RELEASE_CERT_SHA256` values from the release environment.

Debug developer authorization is compiled only from `src/debug` and has no runtime release switch. QA can build with `-PENFORCE_LICENSE_IN_DEBUG=true` and provide a development public key through `-PDEV_LICENSE_AUTHORITY_PUBLIC_KEY=...` to exercise the complete offline flow. No private authority key is accepted or embedded.

## Threat model and limits

- Copying the APK and license to another tablet fails the Keystore-derived device binding.
- Editing expiry, identity, plan, or any signed field fails signature verification.
- Editing preferences cannot forge a signed envelope; trusted-time edits fail its MAC.
- Clock rollback is resisted by the durable maximum floor and monotonic session time.
- Re-signing a modified APK fails the configured release-certificate check; R8 raises patching cost.
- Replaying an older signed lease fails the sequence rule.
- A determined attacker controlling the hardware can theoretically patch every check. Layered UI, repository, cryptographic, integrity, and obfuscation controls make that materially harder; no claim of mathematical unpatchability is made.

Normal evaluation performs no network request, sends no sales data, and includes no payment processing. A future optional online refresh/trusted-time/revocation layer can be added without changing the V1 offline contract.
